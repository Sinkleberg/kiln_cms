## Fixed

<a id="composite-field-keeps-typed-parts"></a>

- **A composite custom field no longer blanks every part, and loses what was
  typed, when one part fails validation.** A field that fails validation is
  left out of the cleaned `custom_fields` map that `ApplyCustomFields` writes
  back. Once the record held a stored value, the editor read that map,
  found the field missing and rendered every part of a composite field, such
  as a business-hours grid or a geolocation, blank. The next change event
  then posted the blanks. In practice the first half-filled day (an opening
  time with no closing time) wiped a whole week of hours that an autosave had
  already stored. `KilnCMSWeb.ContentEditor.Shared.custom_field_value/2` now
  falls back to the submitted value for a field the cleaned map lacks, so the
  parts stay as typed while the error shows. Valid edits are unchanged.
  ([#1923](https://github.com/The-Verscienta/kiln_cms/pull/1923))
